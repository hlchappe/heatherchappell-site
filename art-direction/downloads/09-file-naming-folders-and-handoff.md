## Five rules for every file

1. **Save it in the issue's folder tree,** in the stage folder it belongs to. Nothing lives on a desktop or in a personal folder.
2. **Name it by the pattern in this doc.** A file someone else can't identify from its name alone is misnamed.
3. **Never overwrite a delivered file.** Save a new version number instead.
4. **Never move, rename or delete a file you didn't make.** Older issue files stay where they are until Heather says yes to a cleanup.
5. **Update the art log and the rights log** every time you add, pick, change or place an image.

## 2. File naming

### General rules

- **No spaces in file names.** Use underscores between fields and hyphens inside a field. Layout links and HTML builds break on spaces.
- **Lowercase for slugs,** CAPS only for the process tag. No accents, apostrophes, slashes or emoji.
- **Dates as YYYY-MM-DD** (2026-12-15), in file names and in new folder names.
- **Versions as v01, v02, v03.** Two digits. Raise the number for every changed delivery.
- **Never put a host's last name, a phone number, an email or a location in a file name.**
- **Rename Midjourney downloads right away.** Midjourney's default names carry the account's user name and a long code. Don't keep them in any shared folder.
- **Google Docs and Sheets** use readable titles with spaces (see below). The no-spaces rule is for files that layout or code links to.

### Issue code

`SE-V02` = SIDE EYE, volume 2. Always two digits. Use it at the start of every art and layout file name, and in Drive titles inside the stage tree.

### Image ID

Every image in an issue gets one image ID. 06 Imagery Sourcing, Rights and Credits defines it, and this doc uses the same format.

```
SE-V<vol>-<type><NN>
```

| Part | Rule | Example |
| :- | :- | :- |
| `SE-V<vol>` | Issue code | SE-V02 |
| `-` | One hyphen | |
| `<type>` | One letter from 06, section 2.1: I generated art, H archival image, X composite, P our photo, F found ephemera, S our scan, L hand lettering | H |
| `<NN>` | Two digits, counted per type, in order of first use in the issue | 03 |

Examples: `SE-V02-H03` (the third archival image), `SE-V02-I12` (the twelfth generated image), `SE-V02-X01` (the first composite).

Rules:

- **Give the ID when the image first gets a row** in the art log or the rights log. Never change it after that, even if the page moves.
- **Never reuse an ID,** even for an image you dropped. Mark the dropped row Skip and give the replacement a new ID.
- **Use the same ID in the art log, the rights log, the rights evidence file and the credit list.** The image ID is the key that joins them. The file name is how layout finds the file.
- **Name each rights evidence file by its image ID:** `SE-V<vol>-<type><NN>_rights_<YYYY-MM-DD>.pdf` (or .png for a screenshot), dated the day the rights statement was read. Example: `SE-V02-H03_rights_2026-12-02.pdf`. Save it in 04 Art/06 Rights Evidence.
- **Don't put the image ID in the image file name.** The file name pattern below already says the page, piece, process and version. Record both in the same art log row.

### Art files (generated, archival, composites, finals)

Pattern:

```
SE-V<vol>_<page>_<piece-slug>_<PROCESS>_<variant>_v<NN>.<ext>
```

| Field | Rule | Examples |
| :- | :- | :- |
| `SE-V<vol>` | Issue code | SE-V02 |
| `<page>` | First page where the image is placed, three digits. A spread uses both pages. Covers use `cvr` (front), `bck` (back) or `spn` (spine). Use `p000` until the flatplan gives the image a page. | p014, p014-015, cvr |
| `<piece-slug>` | Short name of the piece and the image, lowercase, hyphens, 24 characters or fewer. Add `-2`, `-3` when one piece has several images on the same page. | bower-resume, ai-dead-newton, potosi-mine-2 |
| `<PROCESS>` | One of: RELIEF, COLLAGE, WOODTYPE, HYBRID, NEWSPRINT for made art; ARCHIVAL for historical images; TEXTURE for paper and ink textures; BUILT for vector or type built by hand in layout | HYBRID, ARCHIVAL |
| `<variant>` | A or B for the prompt it came from, plus the grid number of the pick (1 to 4). Leave it out for ARCHIVAL, TEXTURE and BUILT. | A, B3 |
| `v<NN>` | Version | v01, v03 |
| `<ext>` | See the image specs in section 3 | png, tif, psd |

Examples:

- `SE-V02_p014-015_bower-resume_HYBRID_B2_v03.tif` (a spread opener, from prompt B, grid image 2, third version)
- `SE-V02_p022_potosi-mine_ARCHIVAL_v01.tif` (a historical image, cleaned and resized)
- `SE-V02_cvr_hero-emu_COLLAGE_A4_v02.psd` (the cover hero, layered)
- `SE-V02_p000_cast-cameo-boot_RELIEF_A1_v01.png` (a select not yet given a page)

Rules:

- **The page number is set when the file is first named for placement.** If the flatplan later moves the page, don't rename a file that is already linked in layout. Update the Page(s) column in the art log instead.
- **One file name, one image.** Don't reuse a name for a different picture, even after a delete.
- **Generations** keep the same pattern with the grid number, so a whole Midjourney run is easy to find: `SE-V02_p014-015_bower-resume_HYBRID_B1_v01.png` to `..._B4_v01.png`.
- **Archival originals** keep a second, untouched copy named the way Vol. 1's public-domain folder did: source ID, artist, title. Example: `cma109042 – Honoré Daumier – Art Lovers.jpg`. The working copy then takes the standard pattern.
- **Vol. 1 slot IDs** (V1-010-1, MJ-01 and so on, from the Prompt Workbook) stay as they are. When you reuse a Vol. 1 file, keep its name and note the reuse in the art log.

The current art log's column header reads "File name (p###_piece_v#)". This pattern starts the same way and adds the issue code, process and variant. **Follow this pattern until Heather decides** whether it replaces both the art log's short form and the Workbook slot IDs (open question).

### Logo files

Never rename a logo file. Use the logo pack's own names, which follow `SIDE-EYE_<layout>_<color>[_<background>][_<width>w]`. The Brand Standards hub, section Logo, says which file to use for which job.

### Layout files

| File | Pattern | Example |
| :- | :- | :- |
| Whole-issue layout | `SE-V<vol>_layout_v<NN>.<ext>` | SE-V02_layout_v07.indd |
| Section layout (when an issue is split) | `SE-V<vol>_<pages>_<section>_v<NN>.<ext>` | SE-V02_p014-061_files_v03.indd |
| HTML build folder | `SE-V<vol>_layout_v<NN>/` | SE-V02_layout_v07/ |
| Page spec (agents) | `SE-V<vol>_<page>_pagespec_v<NN>.md` or `.json` | SE-V02_p014-015_pagespec_v02.json |

### Review and print PDFs

These follow the names Vol. 1 already used: `SIDE-EYE-Vol1-MedRes.pdf`, `SIDE-EYE-Vol1-Interior-KDP.pdf`, `SIDE-EYE-Vol1-Cover-KDP.pdf`.

| File | Pattern | Example |
| :- | :- | :- |
| Review PDF (whole issue, lower resolution) | `SIDE-EYE-Vol<N>-MedRes_<YYYY-MM-DD>_v<NN>.pdf` | SIDE-EYE-Vol2-MedRes_2026-12-15_v01.pdf |
| Marked-up review PDF | add `-Review` and the reviewer's role, not their name | SIDE-EYE-Vol2-MedRes-Review-publisher_2026-12-16.pdf |
| Interior for KDP, working | `SIDE-EYE-Vol<N>-Interior-KDP_v<NN>.pdf` | SIDE-EYE-Vol2-Interior-KDP_v03.pdf |
| Cover for KDP, working | `SIDE-EYE-Vol<N>-Cover-KDP_v<NN>.pdf` | SIDE-EYE-Vol2-Cover-KDP_v02.pdf |
| The exact files uploaded to KDP | replace the version with `-final` | SIDE-EYE-Vol2-Interior-KDP-final.pdf |

Only the files actually uploaded to KDP carry `-final`. If a fix is needed after upload, the next upload becomes `-final-2`, and the earlier one moves to _Archive.

PDF technical specs (page size, bleed, fonts, color, flattening) are in 07 Print Production and Prepress (Amazon KDP). This doc covers names and places only.

### Google Docs and Sheets titles

Drive already uses two title styles. Keep both.

| Kind | Title pattern | Example |
| :- | :- | :- |
| Stage-tree working docs | `<NN> <Doc name> – SE-V<vol> <Issue title>` | 00 Art Log – SE-V03 The Mating Issue |
| Standalone issue docs | `SIDE EYE Vol. <N> – <Doc name> v<N> (CURRENT)` | SIDE EYE Vol. 1 – Manuscript v3 (CURRENT) |
| Drafts | add ` – DRAFT, <YYYY-MM-DD>` | ... – DRAFT, 2026-12-03 |
| Replaced docs | rename the old one to `SUPERSEDED – <old title> (use v<N>)` and move it to _Archive | SUPERSEDED – MASTER Writing Style Guide v1 (use v2, CURRENT) |

Rules:

- **Only one doc of each kind is CURRENT at a time.** When you make a new version, mark the old one SUPERSEDED in the same session.
- **Update the Issue Hub link** to the new version at the same time.
- Older titles used dates like "Oct 6". Don't rename them. Use YYYY-MM-DD for new ones.

## 3. Image file specs

Print numbers come from Design System v2 Addendum A. Color conversion and ink limits are in 07.

| Stage | Format | Color | Resolution | Layers |
| :- | :- | :- | :- | :- |
| Generations (03) | PNG, exactly as downloaded. Never re-save as JPEG. | RGB as delivered | Native Midjourney size (use the HD setting for full-page and spread art, per 05) | Flat |
| Selects (04) | Same file as the generation, copied | RGB | Native | Flat |
| Archival originals (05) | The highest-resolution file the holding institution offers, unchanged | As delivered | Largest available | Flat |
| Composites and edits (07) | Layered TIFF or PSD (Affinity users: .afphoto, plus a layered TIFF copy) | RGB working space until the final step | Built at final placed size, 300 ppi or more | **Layered and named:** every source on its own layer, named by its source file name |
| Textures and kit (08) | TIFF or PNG; tileable textures say "tile" in the slug | Grayscale where the texture is one ink | 300 ppi at the largest size used | Flat |
| Finals for layout (09) | Flattened TIFF with LZW compression. For the HTML build route, PNG. | Follow 07 for when and how RGB becomes CMYK. Convert once, never twice. | **300 ppi at placed size.** Full-bleed page: at least 2,588 × 3,375 px. Never below 200 ppi at any size. Line art and document scans: 600 ppi grayscale where possible. | Flat |

More rules:

- **Upscale before you edit,** and sharpen after scaling, never before (Addendum A).
- **Check resolution at placed size,** not at file size. Divide the pixel width by the placed width in inches. Record the pixel size and the yes/no 300 ppi check in the art log.
- **Peach is for period skin on cut-outs only.** Pink is never painted onto period art. See 05 and the hub's color rules.
- **Keep the untouched generation.** Edits happen on a copy in 07 Composites. The pick in 04 Selects is never changed.
- **No generated lettering survives into a final.** If a generation shows letters, a logo or an eye mark, clean it or regenerate it. Real type is added in layout.

## 4. Layout handoff

There are three routes to a finished layout. Pick the one your tools allow and say which one in your handoff note.

### Route 1: Packaged layout file (InDesign or Affinity Publisher)

Deliver a package, not a bare layout file.

- **InDesign:** File > Package. Include copied fonts that may be shared (free-license fonts only), copied linked graphics, an IDML copy, and a review PDF. Name the package folder `SE-V<vol>_layout_v<NN>_package`.
- **Affinity Publisher:** Save as Package, with the same contents and a PDF.
- Every link must resolve inside the package. No missing or modified links.
- Paid fonts (Druk, Tiempos, GT America Mono, the Hamilton Wood Type faces) have no recorded print license. Don't send paid font files. If the layout uses them, list them in the README and say which free stand-in each one maps to (see 04).

### Route 2: HTML build (the Vol. 1 route)

Vol. 1's interior was not built in InDesign. It was an HTML and CSS document, paginated by a script and printed to PDF in Chromium. An AI agent with code tools can use the same route.

Deliver what the Vol. 1 package delivered:

- The layout source (the HTML, the CSS with color tokens at the top, the pagination script, and the build and render scripts).
- The manuscript text files the build reads.
- Every placed image, in folders that match the paths in the CSS.
- The fonts (free-license only).
- The output PDFs.
- A README that says, step by step, how to rebuild the PDFs on a clean machine, and what still needs doing.

Never hard-code a path to a temporary folder or a personal machine. Every path must be relative to the package.

### Route 3: Page spec (agents who can't run layout software)

If you can't produce pages, don't hand back a description. Hand back a **page spec**: an exact, page-by-page build sheet that a designer or a layout script can follow without guessing.

One spec per page, in Markdown with a JSON block, or JSON alone. Pages are single pages in reading order, as KDP wants them. Odd pages are right-hand pages.

Coordinates:

- Units are inches, to three decimals.
- The origin (0, 0) is the **top-left corner of the trimmed page.**
- Bleed elements extend past the trim: to −0.125 at the top, to 11.125 at the bottom, and past the outside edge (to −0.125 on a left-hand page, to 8.625 on a right-hand page). Never bleed into the gutter.
- Give each element's grid columns too. Grid math is in 04 Grid and Typography. Columns are counted 1 to 12 from the gutter side on right-hand pages and from the outside edge on left-hand pages, so column 1 always starts at the left margin.

Every page spec includes:

| Field | What to give |
| :- | :- |
| `issue`, `page`, `side` | SE-V02, 15, right |
| `spread_with` | The facing page number |
| `piece`, `recipe` | The manuscript piece and the page recipe name from 03 |
| `register` | LOUD or QUIET |
| `tab` | Filing tab color and label, or none |
| `pink_focus` | The id of the one element that carries pink, or none for QUIET |
| `inks` | The inks on the page |
| `elements` | Every element, in stacking order from back to front |
| `checks` | Safety, gutter and type-size checks you ran, each true or false |
| `open_items` | Anything you couldn't settle |

Each element includes: `id`, `type` (image, text, rule, shape, logo), `source` (an exact file name from 04 Art/09 Finals, a logo pack file name, or a manuscript reference with the first and last words), `box` (x, y, w, h in inches), `grid` (first column and span), `style` (a named style from 04, such as body, caption, deck), `rotation` in degrees, and `notes`.

Example (a right-hand QUIET page, shortened):

```json
{
  "issue": "SE-V02",
  "page": 15,
  "side": "right",
  "spread_with": 14,
  "piece": "The Mountain",
  "recipe": "QUIET pages",
  "register": "QUIET",
  "tab": {"color": "gray", "label": "Paid For"},
  "pink_focus": "none",
  "inks": ["black", "newsprint gray tint"],
  "elements": [
    {"id": "bg", "type": "shape", "source": "Newsprint Gray tint per 07",
     "box": {"x": 0, "y": -0.125, "w": 8.625, "h": 11.25}, "grid": null,
     "style": "page-tint", "rotation": 0, "notes": "bleeds top, bottom and outside only"},
    {"id": "img1", "type": "image",
     "source": "SE-V02_p015_potosi-mine_ARCHIVAL_v02.tif",
     "box": {"x": 0.375, "y": 0.5, "w": 7.625, "h": 4.5}, "grid": {"start": 1, "span": 12},
     "style": "halftone-photo", "rotation": 0, "notes": "grayscale, coarse halftone"},
    {"id": "cap1", "type": "text",
     "source": "manuscript: The Mountain, caption 1, 'Cerro Rico...' to '...1590s.'",
     "box": {"x": 0.375, "y": 5.1, "w": 3.75, "h": 0.6}, "grid": {"start": 1, "span": 6},
     "style": "caption", "rotation": 0, "notes": "credit line follows the caption"}
  ],
  "checks": {"text_inside_safety": true, "nothing_essential_within_0.5_of_gutter": true,
             "min_type_7pt": true, "one_pink_focus": true},
  "open_items": ["img1 is SE-V02-H03; rights log status still Pending"]
}
```

The values above are for showing the format only. Use 04 for real column positions.

A page spec is finished only when every image in it is in 04 Art/09 Finals and every text box points to approved manuscript text.

## 5. The handoff note

Every delivery, of any size, comes with a handoff note. Use the handoff note template in 11 Templates. Save it in the folder you delivered to, named `SE-V<vol>_handoff_<YYYY-MM-DD>_<what>.md` (or as a Google Doc titled the same way with spaces).

A handoff note answers these questions, in this order:

1. **What this is.** The issue, the pieces or pages, the route (packaged file, HTML build or page spec), and the version.
2. **What's in it.** A list of every file delivered, by exact file name and folder.
3. **What changed** since the last version, in one line per change.
4. **Checks run.** Which checklists from 08 you ran and the result. Any check that failed, and why.
5. **Rights and credits.** Every new image's image ID, rights status (Cleared, Pending or Blocked, per 06) and credit line, matching the rights log.
6. **Art log and rights log.** Which rows you updated, by image ID.
7. **Open items.** Each one with the options, what each costs, and what you did in the meantime.
8. **Rule conflicts you hit.** Which two sources disagreed and which one you followed.
9. **What you need back,** from whom, and by when.
10. **What's next** if you keep the job, or who picks it up if you don't.

Rules:

- **Never write "approved"** unless the art log shows who approved it and when. AI agents never mark anything Approved.
- **No private data** in a handoff note: no personal contact details, no addresses, no account names.
- **Plain words.** Someone who has never seen the issue should understand it.

## 6. Delivery checklist

Run this before every delivery. Run the matching checklists in 08 too.

**Files and names**
- [ ] Every file is in the right stage folder of the issue tree.
- [ ] Every file name follows section 2. No spaces in linked files. No default Midjourney names.
- [ ] No delivered file was overwritten. Old versions are in _Archive.
- [ ] No host last names, contact details or locations in any file name or file.

**Images**
- [ ] Each image's untouched generation is in 03 Generations and its pick in 04 Selects.
- [ ] Each final is in 04 Art/09 Finals at 300 ppi at placed size (200 ppi absolute floor).
- [ ] Composites are layered with named layers.
- [ ] No generated lettering, logos or eye marks in any image.
- [ ] Color handled the way 07 says, converted once.

**Art log and rights log**
- [ ] One row per image slot, with page, status, brief, prompt or source, chosen file, file name, source and license, credit line, pixel size and the 300 ppi check.
- [ ] Every image has an image ID (`SE-V<vol>-<type><NN>`) used the same way in the art log, the rights log and the credit list.
- [ ] Every image has a rights log row. Its status is true (Cleared, Pending or Blocked). Nothing Pending or Blocked goes to print.
- [ ] Every rights statement is saved in 04 Art/06 Rights Evidence, named by image ID.
- [ ] Approved by and Approved on are blank unless Heather or the art director approved it.

**Layout**
- [ ] The route is named (packaged file, HTML build, page spec).
- [ ] All links resolve inside the package. Fonts included only if free-license.
- [ ] Review PDF exported and named by section 2.

**Handoff**
- [ ] Handoff note written and saved next to the delivery.
- [ ] Issue Hub links updated to the new versions.
- [ ] Nothing shared, moved or renamed outside your own files. No sharing settings changed.
