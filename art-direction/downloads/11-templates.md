Version 1.0 draft · November 24, 2026 · Owner: Lena Marsh, Documentation Specialist, Process and Governance
Status: DRAFT for Heather's review

**Who this is for:** Art directors, designers, image makers, rights checkers, production staff, vendors and AI agents working on a SIDE EYE issue.
**Use it when:** A stage in 01 Issue Design Process: From Brief to Print-Ready Files asks you to make one of these files. Copy the template, fill every field, and delete the guidance lines in *italics*.
**Related:** 01 Issue Design Process: From Brief to Print-Ready Files; 05 Art and Illustration Direction (with Midjourney Prompt Standards); 06 Imagery Sourcing, Rights and Credits; 08 Quality Checklists; 09 File Naming, Folders and Handoff Specs; Napoleon Art Direction (model art-direction deliverable); side-eye-art-direction skill.

## How to use these templates

- Copy the block into a new Google Doc or Sheet in the issue folder that doc 09 names. Name the file the way doc 09 says (stage-tree working docs read `<NN> <Doc name> – SE-V<vol> <Issue title>`). Versions are two digits: v01, v02.
- Fill every field. If a field doesn't apply, write "n/a" and why. Never leave it blank.
- Use only role names in templates (Heather, Art Director, Designer / Layout, Illustrator / Image Generator, Rights Checker, Fact-check / Research, Production). Never put a phone number, personal email, home location or a host's last name in any file or file name (Brand Standards hub, "Privacy").
- Status words, in this order: DRAFT, IN REVIEW, APPROVED, LOCKED, SUPERSEDED. Only Heather sets APPROVED or LOCKED. Agents set DRAFT and IN REVIEW only.
- Logs (art log, rights log, Change Log) are Google Sheets: one row per item, the columns below as the header row.

| Template | Made at stage | Who fills it |
|---|---|---|
| 1. Issue Brief | 0 Issue Brief | Art Director |
| 2. Flatplan | 1 Flatplan | Art Director, Designer / Layout |
| 3. Art-Direction Doc | 2 Art Direction | Art Director |
| 4. Image Request and Art Log row | 2 and 3 | Art Director, Illustrator / Image Generator |
| 5. Rights Log row | 2 and 3 | Rights Checker |
| 6. Change Request | Any stage after a gate | Anyone |
| 7. Handoff Note | End of every stage, and any time work changes hands | Whoever hands off |
| 8. Release Note | 8 Release and Archive | Production |

## 2. Flatplan

One row per page. Spreads share a spread number. Keep it as a Sheet.

```markdown
# SE-V## Flatplan v01: <Issue title>
Page count: <#> (even) · Status: DRAFT · Last change: <date>

| Spread | Pages | Section | Piece | Recipe | Register | Tab | Process | Owner | Status |
|---|---|---|---|---|---|---|---|---|---|
| 0 | Cover | Cover | Cover | Cover (COLLAGE) | LOUD | n/a | COLLAGE | Art Director | Not started |
| 1 | 2-3 | Up Front | <piece> | <recipe from doc 03> | LOUD | n/a | WOOD TYPE + RELIEF | Designer / Layout | Not started |
| | | | | | | | | | |
```

Field guide:
- **Spread:** 0 for the cover; then 1, 2, 3 in reading order. Page 1 sits alone (right-hand page).
- **Pages:** printed page numbers, for example 24-25.
- **Section:** Up Front, The Files, Out Back, Cover, Back Cover.
- **Recipe:** the page recipe name from doc 03 (for example Feature opener (historical person), Box Score, QUIET pages, Out Back).
- **Register:** LOUD or QUIET.
- **Tab:** one of the issue's three tabs, or n/a.
- **Process:** RELIEF, COLLAGE, WOOD TYPE, HYBRID or NEWSPRINT. One per image; list the lead process for the page.
- **Owner:** a role name.
- **Status:** Not started, In progress, Ready for review, Approved (Heather only), Blocked (say why in a note).

Change notes (one line per change after approval):

| Date | Change | Decided by | CR number (if any) |
|---|---|---|---|
| | | | |

## 4. Image Request and Art Log row

Every image slot in the issue gets one row in the issue's art log, a Google Sheet in 04 Art (doc 09 sets its name and place). The Art Director fills the request columns in Stage 2. The Illustrator / Image Generator fills the run columns in Stage 3. Doc 05, section 12 owns the run columns; if it changes, doc 05 wins.

### Request columns (Stage 2, Art Director)

| Column | What goes in it |
|---|---|
| Image ID | Same ID as the rights log: issue code, type code, two-digit number, for example SE-V04-I07 (doc 06 sets the pattern) |
| Slot ID and page | The art-direction doc code (I3, C2, H1) and the page or spread |
| Piece | Feature or department title |
| Placement | Full page, half page, spot, cover hero, background |
| Source type | Generated (I), archival (H), composite (X), our photo (P), found (F), scan (S), hand lettering (L) (doc 06, section 2.1) |
| Process and inks | For example RELIEF, pink + cyan |
| What it must show | One sentence |
| What pink marks | One thing |
| Must NOT | Lines from the Scorecard this image must not imply |
| Placed size | Width × height in inches |
| Minimum pixels | Placed size × 300 (full-bleed page: 2,588 × 3,375 px) |
| Aspect ratio | For example 4:5 |
| Needed by | Date |

### Run columns (Stage 3, Illustrator / Image Generator)

| Column | What goes in it |
|---|---|
| Prompt as run | The exact text pasted, with the reference token left as written in doc 05 (for example `[RELIEF STYLE REFERENCE URL]`), never the link itself |
| A or B | Which prompt won, and any fix applied |
| Generator and version | For example Midjourney v8.2 |
| Seed | If the tool shows one; otherwise "not shown" |
| Job ID | The generator's job ID for the picked image, and its grid position (1 to 4) |
| Date | The date generated |
| Run by | Role or vendor name |
| File name | The renamed file, per doc 09 |
| Pixel size and 300 dpi check | Pixels, placed size, pass or fail |
| Edits in layout | Cut-out, composite, color shift to ink builds, cleanup |
| Source and license | "Generated," or the period source and rights line per doc 06 |
| Credit line | Per doc 06 |
| Status | To run · Running · Picked · Needs rerun · Placed · Skip |
| Approved by and date | Filled only by Heather or the person she names |

Copy-ready header row:

```
Image ID | Slot ID and page | Piece | Placement | Source type | Process and inks | What it must show | What pink marks | Must NOT | Placed size | Minimum pixels | Aspect ratio | Needed by | Prompt as run | A or B | Generator and version | Seed | Job ID | Date | Run by | File name | Pixel size and 300 dpi check | Edits in layout | Source and license | Credit line | Status | Approved by and date
```

## 5. Rights Log row

One Sheet per issue, in 04 Art (doc 09 sets the name, for example `00 Rights Log – SE-V04 <Issue title>`). Every image that appears in the issue gets a row, generated art included. These fields follow doc 06, section 5; if doc 06 changes a field or a status word, doc 06 wins.

| Field | What goes in it |
|---|---|
| Image ID | Issue code, a dash, the type code, then a two-digit number in order of first use, for example SE-V04-H01 |
| File name | The exact file name of the placed file (doc 09) |
| Type | I, H, X, P, F, S or L |
| Source | The collection or program, or "SIDE EYE" or "Midjourney v8.2" |
| Creator | Artist, photographer or maker; "Unknown" if unknown; "SIDE EYE" for generated art |
| Title | The institution's title, or a plain description |
| Date | Date made or published, as the institution gives it |
| Holding institution | Who holds the original; n/a for generated art |
| URL | The item page at the institution, not an image file link |
| License or PD basis | The basis in words, plus what the item page says |
| Verified by | The person or agent who did the checks |
| Verified date | The date the rights statement was read and saved |
| Credit line | Exactly as it will print (doc 06, section 10) |
| Where used | Page or spread, and piece |
| Status | Pending, Cleared or Blocked |
| Changes made | Crop, grayscale, halftone, cut out, composite |
| Pixels and effective ppi | Pixel size and ppi at the placed size |
| Notes | Reason for Pending, the open question, the replacement; for generated art, the prompt's code from the art-direction doc |

Rules for this log:
- Only Cleared rows go to print. Pending can sit in a layout comp. Blocked is never placed; keep the row so nobody tries it again.
- Paid licenses are never Cleared (Brand Standards hub, "Image rights").
- The person who verifies reads the rights statement on the item page themselves and saves it as evidence, named by image ID.
- A row goes back to Pending if the crop, caption, page register or source file changes.

Copy-ready header row:

```
Image ID | File name | Type | Source | Creator | Title | Date | Holding institution | URL | License or PD basis | Verified by | Verified date | Credit line | Where used | Status | Changes made | Pixels and effective ppi | Notes
```

## 7. Handoff Note

Put one at the top of every gate request, and with every delivery of any size. Save it in the folder you delivered to, named `SE-V<vol>_handoff_<YYYY-MM-DD>_<what>.md` (or a Google Doc titled the same way with spaces). The questions and their order come from doc 09, section 5; if doc 09 changes them, doc 09 wins. Nothing counts as handed off until it is in Drive.

```markdown
# Handoff · SE-V## · <what> · <YYYY-MM-DD>
From: <role> · To: <role> · Stage: <#> <stage name>

## 1. What this is
Issue, pieces or pages, route (packaged layout file / HTML build / page spec), version.

## 2. What's in it
- <exact file name> · <folder>

## 3. What changed since the last version
- <one line per change>

## 4. Checks run
08 Quality Checklists, Stage <#> <stage name>: <all pass / exceptions>
Failed checks and why: <...>

## 5. Rights and credits
| Image ID | Rights status (Cleared / Pending / Blocked) | Credit line |
|---|---|---|
| | | |

## 6. Art log and rights log
Rows updated, by image ID: <...>

## 7. Open items
| Item | Options | What each costs | What I did meanwhile |
|---|---|---|---|
| | | | |

## 8. Rule conflicts I hit
<which two sources disagreed, and which one I followed>

## 9. What I need back
<what, from whom, by when>
For a gate request: the decision Heather is asked to make, the options, and my recommendation.

## 10. What's next
<next step if I keep the job, or who picks it up>

Status updated in the production tracker: <yes>
```

Rules: never write "approved" unless the art log or the production tracker shows who approved it and when. No private data: no personal contact details, no addresses, no account names.
